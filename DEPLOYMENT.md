# Deployment Guide for DivvyUp

This guide walks you through deploying the DivvyUp app with a **Svelte frontend on Vercel** (free) and a **Node.js/Express backend on Render** (free tier).

## Architecture Overview

- **Frontend**: Svelte + Vite → Deployed to Vercel
- **Backend**: Node.js + Express + Prisma → Deployed to Render
- **Database**: PostgreSQL (Render's free tier)

## Prerequisites

1. **Git repository** pushed to GitHub/GitLab/Bitbucket
2. **Vercel account** (free) - [vercel.com](https://vercel.com)
3. **Render account** (free) - [render.com](https://render.com)

## Step 1: Deploy Backend to Render

### Option A: Using render.yaml (Recommended)

1. **Push your code** to Git (ensure `render.yaml` is in the root)
2. **Go to Render Dashboard**: [dashboard.render.com](https://dashboard.render.com)
3. **Click "New"** → **"Blueprint"**
4. **Connect your repository** and select the branch
5. **Render will automatically**:
   - Create a PostgreSQL database
   - Deploy the backend service
   - Run migrations
   - Set up environment variables

### Option B: Manual Setup

If you prefer manual setup:

1. **Create PostgreSQL Database**:
   - Go to Render Dashboard → "New" → "PostgreSQL"
   - Name: `divvyup-db`
   - Plan: Free
   - Copy the connection string

2. **Create Web Service**:
   - Go to Render Dashboard → "New" → "Web Service"
   - Connect your repository
   - Name: `divvyup-backend`
   - Environment: `Node`
   - Build Command: `cd backend && npm ci && npm run build:production`
   - Start Command: `cd backend && npm run prisma:migrate:production && npm start`

3. **Set Environment Variables**:
   ```
   NODE_ENV=production
   DATABASE_URL=[paste PostgreSQL connection string]
   JWT_SECRET=[generate a strong random string]
   PORT=10000
   CORS_ORIGIN=https://divvyup.vercel.app
   ```

### Get Your Backend URL

After deployment, note your backend URL (something like `https://divvyup-backend.onrender.com`).

## Step 2: Deploy Frontend to Vercel

### Using Vercel Dashboard

1. **Go to Vercel Dashboard**: [vercel.com/dashboard](https://vercel.com/dashboard)
2. **Click "New Project"**
3. **Import your Git repository**
4. **Vercel auto-detects Vite** and uses the `vercel.json` configuration
5. **Set Environment Variable**:
   - Name: `VITE_API_BASE`
   - Value: `https://your-backend-url.onrender.com` (your Render backend URL)
6. **Deploy**

### Using Vercel CLI (Alternative)

```bash
# Install Vercel CLI
npm i -g vercel

# Login
vercel login

# Deploy from project root
vercel

# Set environment variable
vercel env add VITE_API_BASE production
# Enter: https://your-backend-url.onrender.com

# Redeploy to apply env vars
vercel --prod
```

## Step 3: Update CORS Settings

After deploying the frontend, update the backend CORS settings:

1. **Go to Render Dashboard** → Your backend service → "Environment"
2. **Update `CORS_ORIGIN`** to your Vercel URL (e.g., `https://divvyup.vercel.app`)
3. **Redeploy** the backend service

## Step 4: Verify Deployment

1. **Visit your Vercel URL** (e.g., `https://divvyup.vercel.app`)
2. **Test registration/login** to ensure backend connectivity
3. **Check backend health**: Visit `https://your-backend-url.onrender.com/health`

## Database Migrations

**Automatic**: Migrations run automatically on each deployment via the start command:
```
npm run prisma:migrate:production && npm start
```

**Manual**: If needed, access Render's web shell:
1. Go to your service → "Shell"
2. Run: `cd backend && npm run prisma:migrate:production`

## Free Tier Limitations

### Render (Free)
- Service sleeps after 15 minutes of inactivity
- 750 hours/month (sufficient for most use cases)
- PostgreSQL: 1GB storage, 97 connections

### Vercel (Free)
- 100GB bandwidth/month
- Unlimited static deployments
- 12 serverless function executions/day (not applicable for this SPA)

## Troubleshooting

### Common Issues

1. **CORS Errors**:
   - Verify `CORS_ORIGIN` matches your Vercel URL exactly
   - Check that both HTTP and HTTPS protocols match

2. **Database Connection Errors**:
   - Ensure `DATABASE_URL` is correctly set
   - Check that migrations have run successfully

3. **Backend Sleep Issues (Render Free)**:
   - First request after sleep takes ~30 seconds
   - Consider upgrading to paid plan for production apps

4. **Environment Variables Not Applied**:
   - Redeploy after changing environment variables
   - Check spelling and format of variable names

### Debug Commands

```bash
# Check backend health
curl https://your-backend-url.onrender.com/health

# Test CORS
curl -H "Origin: https://divvyup.vercel.app" https://your-backend-url.onrender.com/health

# View database schema
npm run prisma:studio:production
```

## Production Optimization

For production use, consider:

1. **Upgrade to paid tiers** for better performance and uptime
2. **Use a CDN** for static assets (Vercel includes this)
3. **Implement caching** strategies
4. **Add monitoring** with services like Sentry or LogRocket
5. **Set up automated backups** for the database

## Security Considerations

1. **Strong JWT Secret**: Use a cryptographically secure random string
2. **HTTPS Only**: Both Vercel and Render enforce HTTPS by default
3. **Environment Variables**: Never commit secrets to Git
4. **CORS**: Keep CORS_ORIGIN restrictive to your frontend domain
5. **Database**: Use connection pooling for better security and performance

Both platforms offer sufficient free tiers for development and small production apps.

## Automated Deployment with GitHub Actions

For automatic deployments on every code push, see the GitHub Actions workflows in `.github/workflows/`:

- **`full-deploy.yml`**: Complete application deployment (recommended)
- **`deploy-frontend.yml`**: Frontend-only deployment  
- **`deploy-backend.yml`**: Backend-only deployment

### Quick Setup for GitHub Actions

1. **Set up your deployments manually first** (following the steps above)
2. **Add GitHub Secrets** in your repository settings:
   - Vercel: `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `VITE_API_BASE`
   - Render: `RENDER_API_KEY`, `RENDER_SERVICE_ID`, `RENDER_SERVICE_URL`
3. **Push to main branch** - deployments happen automatically!

See `.github/workflows/README.md` for detailed setup instructions and troubleshooting.
